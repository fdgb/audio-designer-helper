# 音效制作瓶颈 · 检索方法论 SOP

> 来源：用户诗悦测试未过后的流程反思 + 湮灭之潮预警音效实战。可复用，活的文档。

## 一、双瓶颈框架

做音效慢，不是创意问题，是**流程**问题。拆成两个独立瓶颈：

| 瓶颈 | 表现 | 解法 |
|------|------|------|
| **搜不到**（检索） | 想好要什么，翻库找不到，卡在角色技能/特定元素 | 拆层 + 索引检索（见下） |
| **组不出**（组合/设计） | 找到了素材，不知道怎么设计/组合成目标 | 分层配方卡（impact/body/texture/tail/air）逐层合成 |

两类打法完全不同，**一个工具救不了俩**。本 SOP 解决"搜不到"。

## 二、检索：两种检索，别混用

### A. 命名概念检索（"门式大冲击""雷电拳脚""警报"）
- **错的做法**：纯频谱相似搜（bandprof 向量找像的）。命名概念频谱形多变，纯相似会捞回一堆"中频平衡像但不是目标"的假阳性——鸟鸣、UI 脆响、纯音、警笛全混进来。
- **对的做法 = 混合检索**：
  1. `files` 表 name/subcat/library **关键词**过滤（`door/slam/impact/hit/knock/thud/bang/metal/wood/crate/hatch/shutter` 等，词边界匹配，下划线也算边界）；
  2. 再叠 `bandprof` **声学门控**：宽带（≥3 段 >0.12 且单段 <0.60 排窄带）+ 中低频 body（b2+b3≥0.12）+ 质心窗（250–4000Hz）+ 时长上限（specs.dur<2.5s）。
  - 实测：关键词命中 6.2 万 → 词边界 1.3 万 → 声学门控 962 条，Top40 全是真·门/冲击/击打。

### B. 参考音相似检索（"找一段像这段的"）
- 用 bandprof / compsim **频谱 + 材质相似**向量检索，给一段参考音找近似。
- 适合"已有目标音色，批量搜同款"。

### 铁律
**命名概念绝不用纯频谱相似搜**；参考音才用。混用 = 浪费一下午捞假阳性。

## 三、索引（检索的地基）

- 全库先扫成 `index.db`：`files`（路径/库别/子类/名）、`specs`（sr/bits/ch/dur，仅少数文件有真实时长）、`bandprof`（8 段频谱 + centroid + flux）、`matprof`（材质特征）。
- ⚠️ `specs.dur` 覆盖极少（实测算 ~1.3 万 / 34 万），纯按时长筛会退化成"文件大小代理"——这是早期门式检索漏掉假阳性的根因之一。时长只作辅助，主判据是声学门控。
- bandprof 是**静态频谱 profile**，抓频率占比，抓不了"瞬态 vs 持续"。瞬态判定要靠 flux + 时长 + body 组合门控。

## 四、语义/role 二次分类层（design_tags）

- 声学相似搜只是初筛；真正把"中频音"滤成"门式冲击"的是 **role 语义层**。
- `design_tags` 表（use_case / style_family / element / role / project / verified / notes / ts）：每次项目从设计讨论抽分解 + 风格 tag，逐项目累积成 warm cache，**不一次性全标 34 万**。
- 约束（诚实）：tagging 需**用户耳朵确认**（human-in-loop），我只能按声学相似提候选。

## 五、粉红噪音校准前置铁律（跨项目）

凡问到"音量平衡 / 响度匹配 / 元素主次 / 混音电平"类问题，**先问"你用粉红噪音校准过没？"**。
根因：没用粉红噪音当客观锚、按画面/手感调 clip gain → 比例成互相矛盾的任意值永远对不上。
逃脱 = RESET + RE-ANCHOR（归零 → 4 总线 → −23 LUFS 粉红定每总线推子锁死 → 某段吵就画总线自动化 ride）。顺序：平衡 → 总线 EQ → 动态 → 限制器（−1.0，bounce 前必挂）。
